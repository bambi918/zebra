改動內容（共 8 處）

🛡️ 版本相容性修復（3 處）

改動 1 gameState 加入 saveVersion let gameState = { ... }

在 gameState 頂端加入版本號，供未來大改版時做版本判斷依據。

Before
let gameState = { day: 1, coins: 1000, ...
After
let gameState = { saveVersion: 2, // ← 新增 day: 1, coins: 1000, ...
改動 2 loadSavedGame — techs 用 id 合併 function loadSavedGame()

舊存檔讀入時，先備份新版 techs 陣列，spread 後再用 id 對齊合併，確保新增的科技對舊玩家也可見。

Before
gameState = { ...gameState, ...tempSaveData }; // ← 整個 techs 陣列被舊存檔覆蓋，新科技消失
After
const defaultTechs = gameState.techs; gameState = { ...gameState, ...tempSaveData }; // 用 id 合併，保留舊等級，補齊新科技 gameState.techs = defaultTechs.map(newTech => { const saved = tempSaveData.techs?.find(t => t.id === newTech.id); return saved ? { ...newTech, lv: saved.lv, cost: saved.cost } : newTech; });
改動 3 讀檔訊息顯示來源 function loadSavedGame()

聊天框顯示存檔是從「雲端」或「本機」載入，方便確認目前使用的存檔來源。

const loadSource = (userId && db) ? '雲端' : '本機'; addChatMessage("系統", `成功從${loadSource}載入圓頂進度！`, "system");

💾 存檔機制修復（3 處）

改動 4 saveGame — 雙寫 localStorage async function saveGame()

每次存檔先寫入 localStorage，再嘗試 Firebase。Gemini Canvas 下會雙備份，其他環境至少有 localStorage。

After
async function saveGame() { const data = JSON.stringify(gameState); // 永遠備份到 localStorage try { localStorage.setItem('sea_life_save_v1', data); } catch(e) {} // 若有 Firebase，同步到雲端 if (!userId || !db) return; ... }
改動 5 checkSave — localStorage fallback async function checkSave()

讀檔時先嘗試 Firebase，失敗或不存在時自動 fallback 到 localStorage，讀到存檔就顯示 Modal，都沒有才開新遊戲。

改動 6 window.onload — 補呼叫 checkSave window.onload = () => { ... }

原本 checkSave() 只在 Firebase 認證成功後才觸發。加這行讓沒有 Firebase 的環境也能正確執行讀檔流程。

// Firebase 未就緒時（本機 / GAS），直接用 localStorage 讀檔 if (!db) { checkSave(); }

📥📤 跨瀏覽器匯出／匯入（2 處）

改動 7 HTML Header 加入兩個按鈕 header 音樂按鈕旁

在音樂按鈕旁新增兩個小按鈕，樣式與現有按鈕一致，不影響主要操作區域。

<!-- 匯出 --> <button onclick="exportSave()">📥 匯出存檔</button> <!-- 匯入（隱藏 input + 觸發按鈕）--> <input type="file" id="save-import" accept=".json" class="hidden" onchange="importSave(event)"> <button onclick="document.getElementById('save-import').click()"> 📤 匯入存檔 </button>
改動 8 exportSave() / importSave() 函數 JS — 新增函數

exportSave()：把目前 gameState 序列化成 JSON 並觸發瀏覽器下載，檔名含天數（如 海中圓頂_第5天_存檔.json）。

importSave()：讀取 .json 檔後執行與 loadSavedGame 相同的 migration 邏輯，還原後同時寫入 localStorage 並更新畫面。含錯誤提示、重置 input 以允許重複匯入。

THREE

後續維護說明

✅ 新增欄位（安全，照做即可）

直接在 gameState 初始物件加新欄位並給預設值。
{ ...gameState, ...tempSaveData } 的機制確保新欄位保留預設值，舊存檔讀入後自動補上。

gameState = { saveVersion: 2, day: 1, newFeature: false, // ← 直接加，舊存檔自動補預設值 ...

✅ 新增科技（安全，照做即可）

直接在 techs 陣列加新項目，改動 2 的 id 合併邏輯會自動處理：舊玩家讀檔後看到新科技且等級為 0，舊科技等級完整保留。

techs: [ { id: 'tourism', ... }, { id: 'garden', ... }, { id: 'space', ... }, { id: 'newtech', name: '新科技', lv: 0, cost: 800, desc: '...' }, // ← 直接加 ]

⚠️ 重新命名欄位（需加 migration）

在 loadSavedGame() 的 spread 行之前加轉換邏輯：

// 範例：舊欄位 coins → 新欄位 dreamCoins if (tempSaveData.coins !== undefined && tempSaveData.dreamCoins === undefined) { tempSaveData.dreamCoins = tempSaveData.coins; delete tempSaveData.coins; }

🔧 重大改版（需升版號）

結構大幅改動時，把 saveVersion 改為 3，並在 loadSavedGame() 加版本判斷：

if (!tempSaveData.saveVersion || tempSaveData.saveVersion < 3) { // v1/v2 → v3 的 migration 邏輯 tempSaveData.residents = tempSaveData.residents.map(r => ({ ...r, newField: 'default' })); }

✅ 新增商店商品或裝潢（安全，完全不影響存檔）

  • shopItemsData 和 mashaItemsData 是程式碼端定義，不存入存檔
  • 加新藍圖：直接加到 shopItemsData 陣列即可
  • 加新裝潢：直接加到 mashaItemsData 陣列即可

📥📤 跨瀏覽器換機流程

  • 在目前瀏覽器點「📥 匯出存檔」→ 下載 海中圓頂_第X天_存檔.json
  • 到新瀏覽器 / 新裝置開啟遊戲
  • 點「📤 匯入存檔」→ 選剛才下載的 .json 檔
  • 遊戲自動還原，同時也寫入新環境的 localStorage

⚠️ localStorage Key 升版提醒： 目前使用 sea_life_save_v1。若日後做不相容的大改版，換成 sea_life_save_v2 以避免讀到格式錯誤的舊存檔。
