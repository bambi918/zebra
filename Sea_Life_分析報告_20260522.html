1-1　手機浮動視窗偏右問題

📸
截圖來源： Screenshot_20260522-102320.png（手機瀏覽 bambi918.github.io）
「歡迎回到海中圓頂」啟動 Modal 整體往右側偏移，未能置中於手機畫面。
檢查項目狀態說明
Modal HTML 結構 ✅ 正確 fixed inset-0 flex items-center justify-center — 寫法無誤
body overflow-x 設定 ⚠️ 不完整 只設在 body，未設在 html
手機瀏覽器行為 💥 根本原因 部分手機瀏覽器將 body 的 overflow-x: hidden 視為新的 containing block，導致 position: fixed 的計算基準偏移
桌面版顯示 ✅ 正常 桌面版不受影響，只有手機才會觸發此行為

根本原因：W3C 規範允許瀏覽器在 body 設有 overflow 時建立新的 formatting context。 Chrome for Android 等手機瀏覽器會據此重新計算 fixed 元素的偏移原點， 若 html 未同步設定 overflow-x: hidden，視口寬度計算就會出現差異，造成右移。

修正內容（共 11 處）

📱 手機顯示修正（1 處）

CSS 修正 html 加入 overflow-x: hidden + body 補 width: 100% <style> 區塊 — body { ... }

手機瀏覽器將 body 的 overflow-x: hidden 視為新的 containing block，導致 position: fixed 的 Modal 偏右。 修正方式是同時在 html 加上相同設定，消除視口計算差異。

Before
body { font-family: 'Noto Sans TC', sans-serif; background-color: #fffafa; color: #0f172a; overflow-x: hidden; margin: 0; }
After
html { overflow-x: hidden; } body { font-family: 'Noto Sans TC', sans-serif; background-color: #fffafa; color: #0f172a; overflow-x: hidden; margin: 0; width: 100%; }

🔴 嚴重 Bug 修正（2 處）

Bug 1 — 高 openDemolishModal — 加入 null guard 防崩潰 function openDemolishModal()

若建築的 bpId 在 shopItemsData 找不到對應項目，直接存取 item.name 會拋出 TypeError: Cannot read properties of undefined，導致拆除模式整個失效且無錯誤提示。

Before
function openDemolishModal(buildingId) { const b = gameState.buildings.find(x => x.id === buildingId); const item = shopItemsData.find(i => i.id === b.bpId); // ← item 可能是 undefined document.getElementById('demolish-target-name').innerText = item.name; // 💥 crash ...
After
function openDemolishModal(buildingId) { const b = gameState.buildings.find(x => x.id === buildingId); const item = b ? shopItemsData.find(i => i.id === b.bpId) : null; if (!b || !item) return; // null guard document.getElementById('demolish-target-name').innerText = item.name; ...
Bug 2 — 高 changeZoom — 修正無效的 calc() 語法 function changeZoom()

calc(100% * 1.5) 是無效的 CSS 語法，CSS calc() 不允許「百分比 × 純數字」的乘法運算， 瀏覽器會靜默忽略整行，縮放拉桿拖動完全沒有視覺效果。

Before
wrapper.style.width = `calc(100% * ${val})`; // ← 無效 CSS wrapper.style.maxWidth = `calc(500px * ${val})`; // ← 無效 CSS
After
wrapper.style.width = `${parseFloat(val) * 100}%`; wrapper.style.maxWidth = `${parseFloat(val) * 500}px`;

🟡 中等 Bug 修正（2 處）

Bug 3 — 中 toggleDemolishMode — 關閉時補呼叫 renderOwnedBlueprints() function toggleDemolishMode() — else 分支

開啟拆除模式時會呼叫 renderOwnedBlueprints() 更新藍圖列表；但關閉時的 else 分支遺漏了這個呼叫， 導致關閉後藍圖的選取狀態不會正確還原。

After（else 分支補上）
} else { btn.classList.remove('bg-red-500', 'text-white', 'border-red-600', 'shadow-inner'); btn.classList.add('bg-slate-100', 'text-slate-500'); btn.innerHTML = '🪓 拆除模式 (關閉)'; renderOwnedBlueprints(); // ← 補上 }
Bug 4 — 中 toggleDemolishMode — 不動態移除 hover class function toggleDemolishMode() — classList 操作

Tailwind CDN 使用 JIT 模式，只會保留在 HTML 原始碼中「靜態出現」的 class 樣式。 若先用 classList.remove('hover:bg-slate-200') 移除，再用 classList.add('hover:bg-slate-200') 重新加回， 這個 class 名稱對應的 CSS 規則已被 purge 而不存在，加回去也沒有效果，按鈕 hover 樣式永久失效。

Before（有誤）
// 開啟時 btn.classList.remove('bg-slate-100', 'text-slate-500', 'hover:bg-slate-200'); // ← 不該移除 hover class // 關閉時 btn.classList.add('bg-slate-100', 'text-slate-500', 'hover:bg-slate-200'); // ← 加回也無效
After（只切換背景色，不碰 hover class）
// 開啟時 btn.classList.remove('bg-slate-100', 'text-slate-500'); // 關閉時 btn.classList.add('bg-slate-100', 'text-slate-500'); // hover:bg-slate-200 留在 HTML 原始碼，永遠不動

🟣 輕微 Bug 修正（2 處）

Bug 5 — 低 renderDomeBuildings — SVG emoji 垂直置中改用 dy 屬性 renderDomeBuildings() — emoji 轉 SVG 邏輯

SVG <text> 使用 dominant-baseline="middle" 在 Chrome for Android / Android WebView 上 有已知渲染問題，會導致 emoji 字符垂直偏移或被截掉上半部。改用 dy="0.35em" 方式置中，相容性更佳。

Before
<text x="50%" y="55%" font-size="75" text-anchor="middle" dominant-baseline="middle">${item.icon}</text>
After
<text x="50%" y="50%" font-size="75" text-anchor="middle" dy="0.35em">${item.icon}</text>
Bug 6 — 低 renderDomeBuildings — 住戶頭像改用 div 包裹確保圓形裁切 renderDomeBuildings() — residentBadge

住戶頭像（canvas.toDataURL() 產生的 base64 圖片）直接套在 <img> 上加 rounded-full， 在手機瀏覽器（尤其 Android Chrome）上 border-radius 不會裁切圖片內容， 導致圖片以原始比例顯示為扭曲的方形色塊。

標準做法是外層加一個 div 並設 overflow-hidden，由 div 的圓角負責裁切，img 只需填滿容器。

📸
截圖來源： Screenshot_20260522-111423.png — 設計圓頂畫面可見建築上出現扭曲方形的住戶圖片
Before
// <img> 直接加 rounded-full — 手機上不裁切 residentBadge = `<img src="${res.img}" class="absolute -top-3 -right-3 w-12 h-12 rounded-full border-[3px] border-white shadow-xl object-cover z-30" onerror="this.style.display='none'">`;
After
// div 負責裁切，img 填滿容器 — 正確圓形 residentBadge = `<div class="absolute -top-3 -right-3 w-12 h-12 rounded-full overflow-hidden border-[3px] border-white shadow-xl z-30"> <img src="${res.img}" class="w-full h-full object-cover" onerror="this.parentElement.style.display='none'"> </div>`;

💬 圓頂頻道機制修正（4 處）

Bug 7+8 — 高 generateDailyChat — 洗牌輪替佇列 + 動態訊息數 generateDailyChat() — fallback 路徑

兩個問題同時解決：① chatCount 上限寫死為 3，人數再多也只有 4~5 則訊息；② 每次純隨機抽籤，同一居民可能連發多則，其他人永遠不被選到。

解法：在 gameState 新增 chatQueue: [] 洗牌佇列，並抽出 pickNextSpeaker() 函數。佇列空時重新洗牌，確保每個居民都發過言才開始下一輪。

Before
// chatCount 上限寫死 const chatCount = Math.min(gameState.residents.length, 3) + Math.floor(Math.random() * 2); for (let i = 0; i < chatCount; i++) { // 純隨機，會重複 const randomRes = gameState.residents[Math.floor(Math.random() * gameState.residents.length)]; ... }
After
// 新增洗牌函數 function pickNextSpeaker() { if (gameState.chatQueue.length === 0) { const indices = gameState.residents.map((_, i) => i); // Fisher-Yates 洗牌 for (let i = indices.length - 1; i > 0; i--) { ... } gameState.chatQueue = indices; } return gameState.residents[gameState.chatQueue.shift()]; } // chatCount 改為動態 const chatCount = Math.min(gameState.residents.length, 5) + Math.floor(Math.random() * 2); for (let i = 0; i < chatCount; i++) { const speaker = pickNextSpeaker(); // 輪替，不重複 ... }
Bug 9 — 低 generateDailyChat — AI 回應解析改用 indexOf(':') generateDailyChat() — AI 路徑 lines.forEach

l.split(':') 不限次數，若 AI 生成的對話內容含冒號（如「今天買了：海鮮披薩」），解構賦值 const [n, c] 只取前兩段，第二個冒號後的內容全部丟失。

Before
const [n, c] = l.split(':'); // 多個冒號時 c 不完整
After
const colonIdx = l.indexOf(':'); const n = l.substring(0, colonIdx).trim(); const c = l.substring(colonIdx + 1).trim(); // 完整保留冒號後的全部內容
Bug 10 — 低 addChatMessage — 移除強制 residents[0] 頭像 fallback addChatMessage() — 居民查找邏輯

AI 模式下，若回傳的名字有些微差異（多空格、加了稱謂），residents.find() 找不到結果，就強制顯示 residents[0]（第一位居民）的頭像，導致任何人發言都顯示同一張臉。

Before
let res = gameState.residents.find(...); if (!res) res = gameState.residents[0]; // 強制用第一人的臉 <img src="${res ? res.img : 'placeholder'}">
After
let res = gameState.residents.find(...); // 移除強制 fallback — 找不到就用佔位圖 <img src="${res ? res.img : 'https://placehold.co/100'}">

後續注意事項

✅ 手機 Modal 置中的通用守則

  • 凡是 body 設有 overflow-x: hidden，html 也必須同步設定
  • 否則手機瀏覽器會建立錯誤的 containing block，所有 position: fixed 的元素都可能位移
  • 保險做法：html, body { overflow-x: hidden; } 寫在一起

⚠️ Tailwind CDN JIT 動態 class 的使用限制

  • Tailwind CDN 只保留「在 HTML 靜態出現」的 class 樣式規則
  • 若要用 JavaScript 動態切換樣式，class 名稱必須事先出現在 HTML 中，不能只靠 JS 動態 add
  • 安全做法：只移除 / 加回「基礎色」class（如 bg-red-500），條件式 class（如 hover:、focus:）保留在 HTML 原始碼，不用 JS 操作

🔧 calc() 乘法的正確寫法

  • calc(100% * 1.5) — ❌ 無效（兩個有單位值相乘）
  • calc(1.5 * 100%) — ✅ 有效（純數字 × 有單位值）
  • 更簡單：直接用 JS 先算好數字再帶入，如 `${val * 100}%`，完全避開 calc 語法問題

🔴 新增「拆除模式」後的未來維護提醒

  • 拆除建築時，該建築的居民不會被自動移除，仍保留在 gameState.residents
  • 被拆除建築的居民狀態目前沒有明確標記（無家可歸），若日後需要顯示「無家可歸」列表，需補充邏輯
  • 拆除費用目前寫死為 100 DC（hardcode），若要動態設定建議提取為常數

📐 圓頂縮放（Zoom）與建築大小統一的關係

  • 縮放倍率由 changeZoom(val) 控制，只影響畫布 wrapper 的寬高，不影響建築的實際座標
  • 建築大小統一由 getExpansionScale() 計算，回傳值隨「圓頂擴張工程」等級提高而增大，讓相對佔地縮小
  • 兩者互相獨立，可同時使用：縮放是「鏡頭拉近」，擴張工程是「房子實際變小」

💬 多人輪替發言的設計原則

  • 純隨機（Math.random()）在小樣本下必然產生「偏心」，人越多越嚴重；10+ 個角色時務必改用洗牌輪替
  • Fisher-Yates shuffle + queue 是最輕量的公平輪替方案：洗牌一次、逐個取出、取完再洗
  • chatQueue 存入 gameState 後會隨存檔持久化，重新載入時佇列不重置，輪替狀態不中斷
  • 居民新增 / 刪除時需清空佇列（queue 裡的舊 index 可能越界），程式碼已在每次 generateDailyChat 進入時自動檢查
